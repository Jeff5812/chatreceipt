# ChatReceipt: Visual Quality, Graphic Craftsmanship and UI Professionalism Standard

You are not simply implementing a functional interface.

You are responsible for delivering a visually exceptional, production-quality digital product.

Act as a combination of:

- Senior Product Designer
- Art Director
- Design Systems Engineer
- Visual UX Specialist
- Frontend Design Engineer
- AI-assisted Design Researcher

Your responsibility is to ensure that every screen, graphic, component, typography choice, colour, spacing decision, and visual interaction contributes to a cohesive, premium product.

The finished interface must not look like a default AI-generated website, a generic SaaS template, or an unfinished developer prototype.

It must look deliberately designed by an experienced product design team.

## 1. Visual quality is a core product requirement

Do not treat visual design as decoration added after functionality.

Visual quality is part of the product itself.

Every implementation must be evaluated for:

- Professionalism
- Visual clarity
- Composition
- Graphic quality
- Image definition
- Depth
- Contrast
- Colour harmony
- Typography
- Spacing
- Alignment
- Hierarchy
- Readability
- Component consistency
- Responsiveness
- Accessibility
- Interaction quality

A feature is not visually complete simply because it renders correctly.

A page can be functional and still be poorly designed.

Do not accept that standard.

## 2. AI models and design research

When a task requires visual research, graphic creation, design exploration, or advanced visual refinement, use the best available tools and models appropriate to the task.

First inspect which tools, models, image-generation capabilities, browser capabilities, and design resources are actually available.

Do not assume a specific model, service, or tool is installed or accessible.

Choose tools based on the intended result.

Use AI for:

- Design exploration.
- Visual concept development.
- Graphic asset creation.
- Illustration.
- Background and texture exploration.
- Product mockup concepts.
- Visual reference analysis.
- Layout alternatives.
- Design critique.
- Refinement of visual direction.

Use image generation when an original visual asset would materially improve the product.

Do not use generated imagery as a substitute for actual interface components.

Do not generate fake screenshots of the application and present them as functioning UI.

Do not use AI-generated graphics when CSS, SVG, HTML, or actual product components would produce a more precise and maintainable result.

All generated assets must be relevant, high quality, consistent with the product identity, and properly integrated.

If a tool is unavailable, continue with the strongest practical alternative. Do not claim to have used tools that were not actually used.

## 3. Eliminate default AI-generated UI

Actively identify and remove generic design patterns.

Avoid:

- Generic hero sections.
- Repetitive three-card layouts without a reason.
- Default-looking headings.
- Generic marketing copy.
- Unnecessary badges.
- Excessive rounded cards.
- Repetitive floating elements.
- Random decorative gradients.
- Purple AI gradients.
- Neon accents.
- Unnecessary glassmorphism.
- Excessive shadows.
- Generic icon usage.
- Placeholder-looking illustrations.
- Unbalanced layouts.
- Excessive empty space.
- Arbitrary font sizes.
- Inconsistent text alignment.
- Repeated component patterns that make every section look identical.

Do not rely on familiar SaaS conventions simply because they are easy to generate.

Every major section should have a clear purpose and a deliberate visual composition.

### Copy and text quality

Remove generic or default-looking UI copy.

Do not leave text such as:

- "Welcome to your dashboard"
- "Unlock the power of AI"
- "Your journey starts here"
- "Revolutionize your workflow"
- "Seamlessly manage everything"
- "Get started today"

unless the wording is genuinely appropriate and has been deliberately chosen.

Use direct, specific, natural language.

Every headline, label, button, helper text, empty state, error message, and description should be written for ChatReceipt's actual user.

Do not use filler text, fake metrics, fabricated testimonials, meaningless descriptions, or placeholder copy in production UI.

Text should sound like a real product serving real people.

## 4. Typography and text composition

Typography must be treated as a design system, not an arbitrary styling choice.

Establish a deliberate typographic hierarchy.

Define:

- Display typography.
- Page headings.
- Section headings.
- Card headings.
- Body text.
- Secondary text.
- Form labels.
- Helper text.
- Metadata.
- Buttons.
- Financial values.
- Document typography.

Use font families with a clear purpose.

For ChatReceipt, the initial direction is:

- Instrument Serif for selected expressive headings.
- Inter for functional interface text.

Evaluate whether this pairing works across the entire product.

Do not use serif typography indiscriminately.

Avoid excessive font weights.

Avoid using too many font families.

### Typography standards

Ensure:

- Appropriate font sizes.
- Consistent font weights.
- Controlled line heights.
- Proper letter spacing.
- Readable line lengths.
- Balanced heading wraps.
- Clear hierarchy.
- Strong contrast.
- Consistent alignment.
- Responsive type scaling.

Do not allow headings to wrap awkwardly.

Do not use oversized text simply to create visual impact.

Do not make body text too small to fit a layout.

Do not allow text to collide with graphics or controls.

Avoid arbitrary text positioning.

Every text element must have a clear relationship to the content around it.

## 5. Colour system, tone and contrast

Establish a professional colour system with clear semantic roles.

Do not choose colours individually for each component.

Use a consistent set of design tokens.

The initial ChatReceipt palette is:

- Warm ivory: #F8F6F1
- White: #FFFFFF
- Charcoal: #191919
- Secondary text: #6B6B68
- Borders: #E5E1D8
- Forest green: #3D5B49

Evaluate this palette against the actual interface.

Refine it if needed, but do not introduce random colours.

Define:

- Primary background.
- Secondary background.
- Elevated surfaces.
- Primary text.
- Secondary text.
- Muted text.
- Border colours.
- Primary action.
- Hover states.
- Focus states.
- Active states.
- Success.
- Warning.
- Error.
- Information.
- Disabled states.

### Colour principles

Use colour with purpose.

Maintain a coherent visual tone.

Avoid:

- Excessive saturation.
- Too many accent colours.
- Low-contrast text.
- Colour combinations that compete for attention.
- Inconsistent status colours.
- Decorative colour without meaning.

Ensure sufficient contrast for readability.

Target WCAG 2.2 AA contrast requirements where applicable:

- At least 4.5:1 for normal text.
- At least 3:1 for large text.
- At least 3:1 for essential interface components and visual indicators.

Do not rely on colour alone to communicate a state.

## 6. Graphic quality, definition and depth

Graphics must look intentional, sharp, and professionally art-directed.

For every graphic, image, illustration, mockup, and visual asset, assess:

- Resolution.
- Sharpness.
- Definition.
- Composition.
- Lighting.
- Contrast.
- Colour harmony.
- Perspective.
- Visual weight.
- Background integration.
- Scale.
- Relevance.
- Consistency with the product.

Avoid:

- Blurry graphics.
- Low-resolution assets.
- Stretched images.
- Poorly cropped images.
- Unbalanced compositions.
- Unnecessary stock imagery.
- Generic AI illustrations.
- Graphics that look disconnected from the interface.

### Visual depth

Use depth selectively and intelligently.

Depth may come from:

- Layered interface surfaces.
- Carefully composed document previews.
- Subtle shadows.
- Border contrast.
- Overlapping elements.
- Foreground and background separation.
- Controlled perspective.
- Soft tonal differences.
- Thoughtful lighting in visual assets.

Depth must improve hierarchy and spatial understanding.

Do not add shadows to every card.

Do not create artificial depth that makes the interface cluttered.

The product should feel dimensional without becoming visually heavy.

### Product graphics

ChatReceipt's strongest visual asset should be the product itself.

Create compelling demonstrations of:

- A conversation screenshot.
- Extracted transaction details.
- An editable review interface.
- A final transaction document.
- A polished export preview.

The transformation from conversation to transaction record should be visually understandable.

Whenever possible, use actual application components in product demonstrations rather than static fake UI.

## 7. Layout, spacing and composition

Establish a consistent spacing system.

Use a deliberate scale rather than arbitrary margins and padding.

Ensure:

- Strong alignment.
- Consistent gutters.
- Balanced whitespace.
- Clear grouping.
- Appropriate content widths.
- Logical section spacing.
- Consistent component dimensions.
- Proper visual rhythm.

Do not force every page into the same layout.

Do not use excessive whitespace to hide a lack of content.

Do not compress content simply to make the page appear modern.

Each layout must be designed around its actual purpose.

### Responsive design

Design for:

- Mobile.
- Tablet.
- Desktop.
- Wide screens.

Do not treat mobile as a scaled-down desktop layout.

Reconsider component hierarchy and interaction patterns for smaller screens.

Avoid:

- Horizontal overflow.
- Clipped text.
- Awkward line wrapping.
- Tiny controls.
- Inconsistent mobile spacing.
- Broken document previews.
- Forms that become difficult to use.

## 8. Component design quality

Every reusable component must have a deliberate visual and behavioural standard.

Review:

- Buttons.
- Inputs.
- Selects.
- Upload zones.
- Cards.
- Navigation.
- Tabs.
- Dialogs.
- Popovers.
- Tooltips.
- Tables.
- Status badges.
- Empty states.
- Error states.
- Loading states.
- Toast notifications.
- Document previews.

Components must have appropriate states:

- Default.
- Hover.
- Focus.
- Active.
- Disabled.
- Loading.
- Error.
- Success.

Do not create a component that looks good only in its default state.

Do not use inconsistent border radii, heights, shadows, typography, or spacing across components.

Use the existing component library where appropriate.

Do not introduce a new UI library without first assessing the current implementation.

## 9. Interaction and motion

Interactions should feel polished, responsive, and purposeful.

Use subtle motion to communicate:

- State changes.
- Progress.
- Feedback.
- Navigation.
- Layering.
- User action.

Avoid:

- Excessive animations.
- Distracting movement.
- Unnecessary parallax.
- Animations that delay user actions.
- Motion that reduces accessibility.

Respect reduced-motion preferences.

Use transitions only where they improve the experience.

The product should feel polished even when motion is disabled.

## 10. Professional UI audit

Before declaring any UI work complete, conduct a visual audit.

Inspect the actual rendered interface.

Do not rely exclusively on reading the code.

Where browser or screenshot tools are available, use them to inspect:

- Overall composition.
- Typography.
- Text wrapping.
- Spacing.
- Contrast.
- Graphics.
- Component alignment.
- Responsive behaviour.
- Loading states.
- Empty states.
- Error states.

Review the page at realistic viewport sizes.

Identify and fix:

- Generic-looking design.
- Inconsistent typography.
- Poor visual hierarchy.
- Low-quality graphics.
- Weak contrast.
- Unnecessary decoration.
- Misaligned components.
- Unbalanced whitespace.
- Awkward text positioning.
- Inconsistent colour usage.
- Excessive visual density.
- Flat or lifeless presentation.
- Broken responsive layouts.

Perform more than one refinement pass when necessary.

Do not stop at the first acceptable rendering.

## 11. Design quality gate

Before completing a visual task, evaluate the result using this checklist.

### Visual craftsmanship

- Does the interface feel professionally art-directed?
- Is the composition intentional?
- Are graphics sharp and high quality?
- Is the visual depth appropriate?
- Is the product visually distinctive?

### Typography

- Is the hierarchy clear?
- Are fonts used consistently?
- Are text sizes appropriate?
- Are line heights and spacing balanced?
- Are headings and labels positioned correctly?
- Is all text readable?

### Colour and contrast

- Is the colour palette cohesive?
- Is contrast sufficient?
- Are semantic colours consistent?
- Are decorative colours restrained?

### Interface quality

- Are components consistent?
- Are interaction states designed?
- Are spacing and alignment precise?
- Is the layout responsive?
- Is the interface accessible?

### Product identity

- Does the UI feel specific to ChatReceipt?
- Does it avoid generic AI-generated patterns?
- Does it communicate trust?
- Does it make the product easier to understand?

If any important criterion fails, refine the implementation before declaring it complete.

## 12. Implementation discipline

Do not rewrite the entire application to improve its appearance.

First inspect the existing codebase.

Identify the design system, components, layouts, typography, assets, and existing visual problems.

Improve the application incrementally.

Preserve working functionality.

Avoid unnecessary dependencies.

Do not create visual changes that break:

- Application logic.
- Form behaviour.
- Accessibility.
- Responsiveness.
- Existing routes.
- API integrations.
- Data handling.

If the task requires a major visual redesign, first produce a clear design direction and implementation plan.

Then implement it in controlled milestones.

## Final standard

The final result should feel like a thoughtfully designed, premium digital product.

It should have strong visual identity, refined typography, excellent composition, appropriate depth, professional graphics, consistent colours, and precise UI craftsmanship.

Do not settle for a functional interface that looks generic.

Do not settle for a beautiful interface that is difficult to use.

The objective is to deliver both.

Every pixel should have a reason to exist.
